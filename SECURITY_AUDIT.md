# Аудит безопасности Pulsar VPN

## Резюме

Ниже — построчный разбор уязвимостей по темам: проверка сертификатов, защита от MITM, аутентификация, утечка трафика при сбое туннеля. В конце — исправления для продакшен-багов (метрики 0, сайты не грузятся при включённом VPN).

---

## 1. Проверка сертификатов и защита от MITM

### 1.1 Конфиг sing-box (TLS/Reality) — `pulsar-daemon/src/config_gen.rs`

**Строки 44–62 (TLS/Reality):**

- **44–54 (Reality):** Параметры `public_key` и `short_id` берутся из ссылки (`params.get("pbk")`, `params.get("sid")`). Если в ссылке их нет, подставляются пустые строки (`unwrap_or(&String::new())`), при этом TLS всё равно включается.
  - **Риск:** Невалидная или пустая конфигурация Reality может ослабить проверку или привести к неожиданному поведению.
  - **Рекомендация:** Для `security == "reality"` явно требовать наличие `pbk` и `sid` и возвращать ошибку генерации конфига, если их нет. Не создавать блок `reality` с пустыми значениями.

- **55–61 (обычный TLS):** Включён только `server_name` (SNI) и uTLS fingerprint. Нет явного указания проверки сертификата.
  - **Риск:** Зависимость от поведения sing-box по умолчанию: если по умолчанию проверка выключена, возможна уязвимость к MITM.
  - **Рекомендация:** В конфиге sing-box явно включить проверку сертификата (например, `insecure: false` или аналог в вашей версии) и не полагаться на дефолты. Документировать требуемую версию sing-box.

- **46, 58:** `server_name` берётся из `sni` из ссылки или подставляется `server_host`.
  - **Рекомендация:** Всегда использовать для TLS именно значение `sni` (или явно `server_host`), чтобы SNI совпадал с именем в сертификате и не было подмены.

### 1.2 Подписка по HTTPS — `pulsar-ui/src-tauri/src/main.rs`

**Строки 100–106 (`fetch_subscription`):**

- **101:** `reqwest::get(&url)` без явной настройки TLS (по умолчанию проверка сертификатов включена в reqwest).
  - **Риск:** При изменении зависимостей или отключении проверки в будущем возможен MITM при загрузке подписки.
  - **Рекомендация:** Явно создать клиент с включённой верификацией и таймаутами, не использовать одноразовый `get()` для пользовательского URL.

- **104:** `STANDARD.decode(resp.trim()).unwrap_or_default()` — при не-base64 вводе декодирование молча возвращает пустой результат.
  - **Рекомендация:** Обрабатывать ошибку декодирования (например, логировать и возвращать `Err`), чтобы не подменять подписку «битой» строкой.

## 2. Аутентификация UI ↔ Daemon (gRPC)

### 2.1 Клиент отправляет токен — `pulsar-ui/src-tauri/src/main.rs`

**Строки 18–24 (`AuthInterceptor`):**

- Токен генерируется как `pulsar-{pid}-{nanos}` (строка 113) и передаётся в заголовке `x-pulsar-token`.
  - **Плюс:** Токен непредсказуем для стороннего процесса.

**Строка 183:**

- `Channel::from_static("http://[::1]:50051")` — соединение только по localhost, без TLS.
  - **Плюс:** Ограничение по интерфейсу снижает риск доступа из сети.
  - **Риск:** Любое приложение на том же хосте может подключиться к порту 50051.

### 2.2 Демон не проверяет токен — `pulsar-daemon/src/main.rs`

**Строки 203–211 (запуск сервера):**

- `Server::builder().add_service(VpnServiceServer::new(service))` — нет interceptors/middleware, метаданные запросов не проверяются.
  - **Уязвимость:** Демон не проверяет заголовок `x-pulsar-token`. Любой процесс на машине может вызывать `ToggleConnection`, `Shutdown`, `StreamMetrics` и т.д.
  - **Рекомендация:**
    1. Передавать секрет от UI в демон при старте (аргумент командной строки или переменная окружения).
    2. В демоне добавить tower/tonic interceptor: извлекать `x-pulsar-token` из метаданных и сравнивать с ожидаемым значением; при несовпадении возвращать `Status::unauthenticated()`.
    3. Не логировать токен и не передавать его по сети за пределы localhost.

**Строка 194:** Демон слушает `[::1]:50051`. **(Исправлено в коде:** демон читает токен из `std::env::args().nth(1)` и проверяет заголовок `x-pulsar-token` в каждом RPC через `check_token()`; при несовпадении возвращается `Status::unauthenticated`.)

## 3. Утечка трафика при сбое туннеля (Kill Switch)

### 3.1 Настройка в UI — `pulsar-ui/src/App.vue`

**Строки 55–59, 438–446 (`settings.killSwitch`):**

- Опция «Kill Switch» только сохраняется в настройках (`saveData()`), в коде нет логики блокировки трафика при падении VPN.
  - **Уязвимость:** При обрыве туннеля трафик может уйти в обычный интерфейс (утечка), пока пользователь думает, что Kill Switch включён.
  - **Рекомендация:** Либо реализовать настоящий kill switch (например, через правила firewall или политику маршрутизации при падении sing-box), либо переименовать опцию в «Block traffic when VPN disconnects (planned)» и не создавать впечатление защиты.

### 3.2 Маршрутизация и DNS — `pulsar-daemon/src/config_gen.rs`

**Строки 131–132 (`strict_route`):**

- `"strict_route": false` — маршруты могут перекрываться с системными.
  - **Риск:** При падении TUN часть трафика может уйти не туда или «просачиваться» на физический интерфейс в переходный момент.
  - **Рекомендация:** Включить `strict_route: true` и проверить поведение на целевых ОС (Windows), чтобы при падении туннеля трафик не шёл мимо VPN без явного решения.

**Строки 134–141 (`route_exclude_address`):**

- Исключены частные и loopback-диапазоны.
  - **Рекомендация:** Оставить как есть и не расширять исключения без необходимости, чтобы не направлять лишний трафик в обход туннеля.

**Строки 89–114 (Правила маршрутизации — приоритет для служебного трафика):**

- **(Исправлено в коде:** Правила переупорядочены для защиты трафика между компонентами приложения.)
  - **ПРАВИЛО 1 (высший приоритет):** `process_name` для `pulsar-ui.exe`, `pulsar-daemon.exe`, `sing-box.exe` → `direct`. Гарантирует, что gRPC между UI и демоном (`[::1]:50051`) не пойдет через VPN.
  - **ПРАВИЛО 2:** `ip_cidr` для `127.0.0.0/8` и `::1/128` → `direct`. Дополнительная защита localhost трафика.
  - **ПРАВИЛО 3:** Локальные сети и домен VPN сервера → `direct`.
  - **Взаимодействие с `route_exclude_address`:** `route_exclude_address` исключает адреса из захвата TUN (первая линия защиты), а правила маршрутизации перенаправляют трафик в `direct`, если он все же попал в TUN (вторая линия защиты). Это обеспечивает двойную защиту служебного трафика.

### 3.3 Мониторинг процесса sing-box — `pulsar-daemon/src/main.rs`

**Строки 95–110:**

- После `spawn()` делается только одна проверка через 1 с (`try_wait()`). Дальше процесс не опрашивается.
  - **Риск:** Если sing-box упадёт позже, демон не узнает об этом и не обновит состояние (и не отключит туннель в UI), возможна утечка при «мнимом» подключении.
  - **Рекомендация:** В фоне периодически проверять `child.try_wait()`. При завершении процесса: сбросить `is_connected`, по возможности уведомить UI (отдельный RPC или закрытие стрима метрик) и, если включён kill switch, применить политику блокировки (если она будет реализована).

## 4. Другие замечания

### 4.1 Профиль (profile_link) — `pulsar-daemon/src/config_gen.rs`, `pulsar-daemon/src/main.rs`

**config_gen.rs, строка 8:** Ссылка парсится и передаётся в sing-box. В `main.rs` строка 68 — `req.profile_link` передаётся без дополнительной валидации.

  - **Рекомендация:** Проверять схему (`vless`), наличие хоста и при необходимости длину/формат строки, чтобы не передавать в конфиг произвольные данные.

### 4.2 Пинг — `pulsar-ui/src-tauri/src/main.rs`, строки 88–97

- Пинг — это только TCP connect к `host:port` (часто 443). Не проверяется доступность именно VLESS/сервиса.
  - **Рекомендация:** Считать пинг ориентировочным; при необходимости добавить отдельную проверку (например, кратковременное подключение к VLESS).

### 4.3 Запись конфига — `pulsar-daemon/src/main.rs`, строка 76

- Конфиг пишется в `%LOCALAPPDATA%\PulsarVPN\config.json` с правами пользователя.
  - **Рекомендация:** Убедиться, что каталог и файл не доступны на чтение другим пользователям (стандартные права Windows обычно достаточны).

## 5. Исправления продакшен-багов (отдельно в коде)

Ниже в коде внесены правки по двум проблемам:

1. **Метрики всегда 0:**  
   - Демон: считать трафик только по интерфейсу TUN (имя содержит `pulsar`), убрать деление на 2, при отсутствии TUN отправлять 0.  
   - UI: повторно вызывать `start_metrics_stream` до успеха (например, раз в 2 с), чтобы поток метрик стартовал после готовности демона.

2. **Сайты не грузятся при включённом VPN:**  
   - В конфиге sing-box включён `strict_route: true` для однозначной маршрутизации.  
   - Проверена логика `final`/режимов (Global/Bypass/Proxy) — оставлена без изменений.

Итог правок: см. диффы в `pulsar-daemon/src/main.rs`, `pulsar-ui/src-tauri/src/main.rs`, `pulsar-ui/src/App.vue`, `pulsar-daemon/src/config_gen.rs`.

## 6. Если при включённом VPN сайты не грузятся

- **strict_route: true** включён для однозначной маршрутизации; на части сетей (например, с особыми маршрутами) это может мешать. Тогда в `config_gen.rs` можно временно вернуть `strict_route: false` и проверить.
- **DNS:** Все запросы по умолчанию идут в `dns-remote` (1.1.1.1 через proxy). При медленном или нестабильном proxy DNS может «висеть». Стоит проверить логи sing-box и доступность 1.1.1.1 через выбранный узел.
- **IPv6:** В конфиге используется `"stack": "mixed"`. Если проблема только по IPv6, можно попробовать для TUN вариант с поддержкой только IPv4 (если sing-box это позволяет в вашей версии).
- **Маршруты:** Убедиться, что после подключения VPN в системе появляется маршрут по умолчанию через интерфейс TUN (например, `route print` в Windows) и что нет блокировки в брандмауэре для sing-box / TUN.
